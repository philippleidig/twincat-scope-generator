# Spec V2.1 — browser views, ADS-accurate catalog, project editing

Planning map: [`.scratch/browser-editor-v2-1/map.md`](../../.scratch/browser-editor-v2-1/map.md).
Vocabulary: [`GLOSSARY.md`](../../GLOSSARY.md). Architecture: [`README.md`](../../README.md#architecture), [`docs/adr`](../adr).

The work is split into **slices**. Each slice is implemented in its own session on its own branch,
reviewed (thermo-nuclear: correctness pass + code-quality pass), fixed, and then pushed to `main`.

General rules for every slice:

- Keep the layering: `domain` (pure) ← `catalog` ← `export` ← `state` ← `features`/`ui`. Stores never
  import features; features never import other features' internals.
- New behaviour comes with tests (unit for domain/catalog/state, component tests for UI); coverage
  thresholds in `vitest.config.ts` must keep passing. Update e2e specs when flows change.
- `npm run lint`, `npx tsc -b`, `npm test`, `npm run build` must pass before handing back.
- Update `CHANGELOG.md` (section `V2.1`), README feature list and `GLOSSARY.md` when terms change.
- No file over ~400 lines without a reason; no new dependencies without a reason stated in the commit.

## Slice A — ADS-accurate catalog, tested on a real-file corpus

**Goal:** the browser offers exactly what can be recorded by ADS symbol name; the importers are
exercised against a large corpus of real files.

### A1. Accessibility rules

From research ticket 05 (report with sources: `.scratch/browser-editor-v2-1/issues/05-ads-access-report.md`)
and the corpus run (ticket 06). **Hide** = not in tree, list, search or candidates. **Disabled** = shown
muted with the reason, not selectable (like strings today). Each row needs a unit test with a minimal XML snippet.

| Construct in the `.tmc` | Markup | Browser behaviour |
|---|---|---|
| Property without monitoring pragma / `monitoring := 'variable'` in an FB | only `<Method>` entries (`__getX`), no member | Hide (already the case — add a test) |
| Property with `monitoring := 'call'` | `<PropertyItem><Name>…</Name><Type>…</Type><GetCodeOffs>…` inside the FB's `<DataType>` | **Disabled**: "Property (called on access) — Scope cannot sample it" |
| Methods, their parameters/locals | `<Method>` | Hide (already) |
| VAR_INST | SubItem with property `implicit_inst_var` | Hide |
| VAR_STAT in an FB | SubItem `<Name Static="true">`, no `<BitOffs>` | **Disabled** below instances: "Static variable — record `<FBType>.<var>`" (the global `<Symbol>FB_x.var` with `TcVarStatic` stays a normal root) |
| `hide` / `hide_all_locals` | `<Property><Name>hide</Name>` on Symbol, SubItem or DataType | Hide the symbol/member; a DataType marked `hide` hides every symbol/member of that type |
| `conditionalshow` (+ `_all_locals`) | property on SubItem/DataType/Symbol | **Disabled**: "Hidden in compiled libraries" |
| `TcNoSymbol` | `<Property><Name>tc_no_symbol</Name>` (no value) | Hide; with value `unused`: show with a note |
| POINTER TO | `<Type PointerTo="n">` **or** a type name starting `POINTER TO` (also when defined in `<DataTypes>` — corpus bug: such types currently resolve as arrays) | The pointer itself: disabled ("Pointer — expand `^` to record the target"); expandable with one child `^` whose path is `<path>^` and whose type is the pointed-to type (`PointerTo="2"` → `^^` via two levels). Search index includes `^` paths. |
| REFERENCE TO / VAR_IN_OUT | `<Type ReferenceTo="true">`, or `ItemType=InOut` | Expand like the referenced type (no `^` in the path); entries carry `viaReference: true` and show a warning icon/tooltip "Valid only while the reference is bound" — still recordable |
| Interface-typed member | type with `<ExtendsType>PVOID` and no SubItems | Disabled (already) |
| STRING / WSTRING | `STRING(n)` | Disabled with reason "Strings can only be shown in table charts" (adjust text) |
| BIT, ENUM, ALIAS/subrange, UNION, TIME/LTIME/DATE/TOD/DT | — | Show (already); add tests for BIT member and union |
| Empty array (`Elements` 0) | `<ArrayInfo>` with 0 elements | Hide (corpus: 38 entries produced invalid templates) |
| `qualified_only`, `<Hides><Hide GUID>`, CODESYS `symbol` attribute | — | Ignore (no effect on paths) |

Implementation notes:
- Keep the decision in one place: extend `ResolvedType`/`MemberDef` with what the walker needs
  (`hidden`, `disabledReason`, `pointerTo`, `viaReference`) in `catalog/typeTable.ts`; `catalog/walk.ts`
  applies it, so tree, search index and candidates agree automatically.
- Members marked hidden are dropped when the type table is built; disabled ones resolve to
  `{ kind: 'unsupported', reason }` (rename the kind if a clearer name helps, e.g. `'disabled'`).
- `resolvePath` must understand `^` segments.

### A2. Corpus tests

- `scripts/corpus/manifest.json` — **already committed**: 352 real files (raw URL pinned to a commit, repo,
  SPDX licence or null, kind, size) from research ticket 06. Files without a permissive licence are only
  downloaded for local testing, never committed.
- `scripts/corpus/fetch.mjs` — downloads the manifest into `.corpus/` (git-ignored); idempotent, checks size.
- `src/catalog/corpus.test.ts` — runs only when `.corpus/` exists (`describe.skipIf`): every file imports
  without throwing; sources have plausible ports and kinds; every scalar search entry's template either
  validates or is an array over `MAX_EXPANSION` (reported, not silently invalid — empty arrays must be
  gone); `resolvePath` resolves every index entry (sample ≤ 2,000 per file); no path contains a hidden
  construct; prints a summary table (files, sources, roots, entries, disabled reasons). Invariants, not
  snapshots. Baseline today: 352 files, 0 import errors, 642k entries, 870 invalid templates.
- The corpus test must stay well under a few minutes (import + index of all 352 files took ~70 s in
  jsdom); give it its own vitest config/timeout so `npm test` is unaffected.
- Permissively licensed files that exercise new rules may be added to `src/catalog/__fixtures__/`
  (update its README and `licenses/`).
- `npm run test:corpus` script = fetch + run the corpus test.

### Acceptance
- Corpus test passes on the full manifest; regular `npm test` stays fast and offline.
- Unit tests cover each row of the A1 table with a minimal XML fixture.

## Slice B — Tree or flat list in the symbol browser

**Goal:** the user switches the browser between the hierarchical tree and a flat list.

- A segmented control **Tree | List** in the browser toolbar (next to the search box).
- **List** shows every search-index entry (the same rows as search results: path, type, area, port,
  array badge ×N; arrays as patterns), sorted by path, virtualised. Search text and filter chips narrow
  it. With an empty query and no filters the list shows all entries (capped like search results, with
  the "Showing n of m" hint).
- **Tree** behaves as today. Typing a query or enabling a filter still switches the tree to results;
  in List mode the list simply filters (no mode switch).
- Selection, focus/Inspector, drag to axis groups and "Add to scope" work identically in both views
  (both produce the same `BrowserPick`s).
- The choice persists per browser (localStorage, try/catch; works without storage).
- Optional: a "Recordable only" default in list mode is **not** applied automatically.

### Acceptance
- Component tests: toggle, list shows all entries without a query, filters narrow, selection survives
  switching views, preference restored on reload.
- e2e: switch to List, select two rows, add them.

## Slice C — Drag & drop in the scope project

**Goal:** reorganise the project by dragging.

- **Channels:** drag a channel row (drag handle on the left of the row) to
  - another position in the same axis group (reorder; drop indicator line between rows),
  - another axis group (insert at the indicated position, or append when dropped on the header/body),
  - a scope file **tab** (appends to that file's first axis group; the tab highlights while hovering).
- **Axis groups:** drag by the group header handle to reorder within the file, or onto a file tab to
  move the group to that file (appended).
- **Copy instead of move:** holding Ctrl (Win/Linux) or Alt/Option (macOS) at drop time copies (new ids).
  The drop indicator shows a "+" badge while copying.
- Browser symbols keep dropping onto axis groups as today (and may now also drop on a precise position).
- **Keyboard/menu alternative:** each channel and axis group gets a "Move to…" menu entry listing axis
  groups / files (accessibility; no drag required).
- Domain: pure ops `moveChannel(p, id, toGroupId, index?)`, `copyChannel(…)`,
  `moveAxisGroup(p, id, toFileId, index?)`, `copyAxisGroup(…)`; atomic; selection normalised after each.
- Drag payloads are plain JSON with their own MIME types (`application/x-scope-channel`,
  `application/x-scope-axis-group`); no module-level drag state.

### Acceptance
- Unit tests for every op incl. edge cases (same position, last position, move into own file, unknown ids).
- Component tests with `fireEvent.dragStart/dragOver/drop` for reorder, cross-group, cross-file via tab,
  copy modifier.
- e2e: reorder two channels and move one to another file.

## Slice D — Channel names and colours

**Goal:** every channel can carry a display name (with counters) and a colour, exported to Scope.

Model (`domain/project.ts`):
- `Channel.name?: string` — display name template; may reference the template's counters as `{i}`
  (no range). Validation: referenced counters must exist in the symbol template.
- `Channel.color?: string` — `#rrggbb`. When unset, the exporter assigns palette colours as today.
- Expansion: `expandChannel(channel)` yields `{ symbolName, displayName, color }` per acquisition;
  for pattern channels the colour of acquisition k is the channel colour for k = 0 and the next palette
  colours after it (palette starting at the chosen colour), unless "same colour for all" (`colorMode: 'same' | 'palette'`, default `'palette'`).
- `parseProject` accepts and validates the new fields (old files without them stay valid).

Export (`export/tcscopex.ts`), from research ticket 07:
- Channel `<Name>` = display name (fallback: symbol name); channel-level `NameRelationInfo`
  `UsedNameType` = `Custom` when a name is set, else `Acquisition`.
- `<Channel><DisplayColor>`, `<SeriesStyle><DisplayColor>` and `<MarkColor>` = signed 32-bit ARGB of the
  colour (alpha 255). Acquisition names stay the symbol names.
- Update the golden file deliberately and add assertions for the new elements.

UI (`features/project/ChannelRow.tsx` and a small popover/expander per channel):
- Colour swatch button at the start of the row opening a colour picker (palette of ~16 + native
  `<input type="color">`) and the "same colour for all" toggle for patterns.
- Name field (optional, placeholder shows the effective name), with counter hint and validation.
- The row stays compact: name and colour live in a collapsible second line or popover.

### Acceptance
- Unit tests: expansion of names/colours incl. counters, padding, palette wrap; parse/serialise.
- Export tests: custom name → `Custom`, colour → ARGB in all three places; XML still well-formed.
- Component tests: set name/colour, see effective name, validation error for unknown counter.
